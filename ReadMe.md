## Функциональные требования

### Статические правила рекомендаций:
- **Invest 500**: DEBIT продукты + нет INVEST + SAVING пополнения > 1,000 ₽
- **Top Saving**: DEBIT продукты + (DEBIT пополнения ≥ 50,000 ₽ ИЛИ SAVING пополнения ≥ 50,000 ₽) + DEBIT пополнения > трат
- **Простой кредит**: Нет CREDIT + DEBIT пополнения > трат + DEBIT траты > 100,000 ₽

### Динамические правила:
- **4 типа запросов**: USER_OF, ACTIVE_USER_OF, TRANSACTION_SUM_COMPARE, TRANSACTION_SUM_COMPARE_DEPOSIT_WITHDRAW
- **REST API**: POST/GET/DELETE /rule

### Telegram Bot:
- Команды: `/start`, `/recommend username`
- Форматированные ответы с HTML разметкой


### Технологический стек:
- **Spring Boot 3.5.7** + **Java 17**
- **Базы данных**: H2 (read-only транзакции) + PostgreSQL (динамические правила)
- **Кеширование**: Caffeine
- **Миграции**: Liquibase
- **Тестирование**: JUnit 5, Mockito
- **Telegram**: telegrambots-spring-boot-starter


## База данных

### БД динамических правил (PostgreSQL):
- Тип: PostgreSQL
- Режим: Read-write
- Назначение: Хранение динамических правил рекомендаций
- Миграции: Liquibase
- JPA: Hibernate для ORM

### Продакшн база:

- Файл: `src/main/resources/transaction.mv.db`
- Пользователи: 1000
- Продукты: 20
- Транзакции: 10093
- Режим: только для чтения


### Тестовая база (Liquibase):
- In-memory H2 с предзаполненными тестовыми данными
- Автоматическое создание таблиц и данных для тестов

## API Endpoints

### Рекомендации:
- `GET /recommendation/{userId}` - получить рекомендации

### Управление правилами:
- `POST /rule` - создать динамическое правило
- `GET /rule` - получить все правила
- `DELETE /rule/{id}` - удалить правило

### Управление сервисом:
- `GET /management/info` - информация о сборке
- `POST /management/clear-caches` - сброс кешей

#  Запуск проекта
## 1 Настройка окружения
### 1.1 Генерация файлов среды окружения:
Запустите `setup-env.sh`, в корне проекта появятся два файла:
- configuration.env - для продакшена
- configuration.env.dev - для разработки 

```bash
  ./scripts/setup-env.sh
```
### 1.2 Редактирование конфигурации
#### После выполнения скрипта отредактируйте созданные файлы:
### configuration.env: 
- Основной файл. По умолчанию, активный ПРОФИЛЬ не установлен.
- Установите профиль `SPRING_PROFILES_ACTIVE=prod` и тогда будут загружаться те базы данных,
  тот телеграмм бот, уровни логирования и настройки кэша, которые вы укажете в `ЭТОМ ФАЙЛЕ` ниже.
- Если указать `SPRING_PROFILES_ACTIVE=dev`,
  то Вы загрузите настройки и базы из файла конфигурации `configuration.env.dev`.

### configuration.env.dev:
- Дополнительный файл конфигурации окружения. По умолчанию, активный ПРОФИЛЬ не установлен.
- Установите профиль `SPRING_PROFILES_ACTIVE=dev` и укажите те базы данных, тот телеграмм бот,
  уровни логирования и настройки кэша, которые используются при разработке. 
- Если не планируете использовать данный профиль, просто не заполняйте настройки.
  `SPRING_PROFILES_ACTIVE=` оставьте пустым.


## macOS/Linux
```bash

nano configuration.env
nano configuration.env.dev
```

## Windows

notepad configuration.env
notepad configuration.env.dev

### Ключевые архитектурные решения:

1. **Разделение ответственности**: Четкое разделение на слои (Presentation, Service, Business Rules, Data Access)

2. **Двойная БД стратегия**:
    - H2 для read-only транзакционных данных
    - PostgreSQL для read-write динамических правил

3. **Гибкая система правил**:
    - Статические правила (hardcoded бизнес-логика)
    - Динамические правила (конфигурируемые через API)
    - Единый интерфейс для обоих типов

4. **Паттерн Команда для Telegram**: Обработчики команд как независимые компоненты

5. **Кеширование с составными ключами**: Оптимизация частых запросов к БД

6. **Конфигурация через .env**: Гибкая настройка для разных окружений

7. **Фабрика исполнителей**: Динамическое создание обработчиков запросов правил
